# Живой переводчик DE↔RU в телефонном звонке

Отдельный маленький сервер (не часть сайта и не деплоится на Vercel): Twilio соединяет два
звонка, звук каждого идёт через OpenAI `gpt-realtime-translate`, и каждый слышит только свой язык.
Аудио и текст разговора нигде не сохраняются и не пишутся в лог.

## Сценарии

- **Исходящий.** Владелец звонит со своего мобильного на номер переводчика, набирает номер
  собеседника и `#`. Собеседник слышит объявление про ИИ-переводчика, затем идёт перевод.
  С чужих номеров набор не работает; платные номера (0900, 0137, 0180, 118…) и заграница закрыты.
- **Входящий.** Владелец отклоняет звонок на мобильном, условная переадресация «при занятости»
  отправляет его на номер переводчика. Собеседник слышит объявление и ждёт, сервер перезванивает
  владельцу. Не взял — собеседник уходит на `SECRETARY_NUMBER` (телефонный ассистент).
- **Тест без входящего номера.** `POST /admin/call` с заголовком `Authorization: Bearer <ADMIN_TOKEN>`
  и телом `{"to":"+49…"}`: сервер звонит владельцу, после ответа — на указанный номер.

## iOS-приложение

**Звонок через интернет.** Приложение звонит через Twilio Voice SDK: токен берёт с `GET /api/voice-token`
(ключ `CALL_KEY`), Twilio передаёт звонок TwiML-приложению «Dolmetscher iOS-App» на `POST /voice/client`
(параметры `to`, `mode`, звонящий `client:owner`), сервер сразу набирает собеседника с вашим мобильным в
определителе. Конец звонка приходит на `/voice/client-status`. Нужны переменные `TWILIO_API_KEY`,
`TWILIO_API_SECRET`, `TWILIO_TWIML_APP_SID` (ключ и приложение созданы через REST API Twilio 16.10.2026),
`CLIENT_IDENTITY`, `CLIENT_RATE`. **Входящие в приложение** (с 16.10.2026): переадресованный звонок сначала звонит в приложение
(`client:owner`, VoIP-пуш через Twilio Push Credential `TWILIO_PUSH_CREDENTIAL_SID`, сертификат
«VoIP Services» для `Viacheslav.Dolmetscher`, sandbox — для сборок из Xcode). Не ответило за
`CLIENT_RING_SECONDS` (20 с) — звонок на мобильный, затем на ассистента. Отклонено в приложении —
сразу ассистент. Для сборок через TestFlight/App Store нужна вторая Push Credential без sandbox.


Нативный клиент — [dolmetscher-ios/](../dolmetscher-ios/README.md): клавиатура, контакты, история
звонков, тарифы и живой текст разговора. Его JSON-маршруты описаны там же, код — `src/api.mjs`.

## Помощь в разговоре (приложение)

- `POST /api/say {text}` — текст владельца переводится на немецкий (номера по цифрам, даты словами),
  озвучивается и проигрывается собеседнику; `{phrase}` — готовая фраза из `src/phrases.mjs`
  (озвучены при запуске, звучат сразу); `GET /api/phrases` — список.
- `POST /api/wait {on}` — «ждать за меня»: перевод выключается, `src/assist.mjs` режет линию на
  куски, распознаёт и спрашивает модель, ответил ли человек. Ответил — владелец слышит «Ответил
  человек!», сотруднику читается предупреждение про ИИ, затем «Можно говорить». В живой текст идут
  события `said`, `wait`, `human`. `MAX_CALL_SECONDS=3600`, чтобы очередь не обрывалась.

## Запуск

```bash
cd interpreter
npm install
cp .env.example .env   # значения вписывает владелец
npm start
```

Серверу нужен публичный HTTPS-адрес с поддержкой WebSocket (`PUBLIC_URL`). В Twilio у номера
переводчика: Voice → A call comes in → Webhook `POST <PUBLIC_URL>/voice/incoming`.

## Известные ограничения прототипа

- Пока перевод не начался, слушающий слышит тишину: оригинальный голос не подмешивается.
- Состояние разговоров хранится в памяти: перезапуск сервера обрывает текущий звонок.
- Задержка и качество перевода на живом звонке ещё не измерены.
